# Lattice — Notes

An experimental graphical composition on a tonnetz-like lattice. Three sine
voices each inhabit one of the three coordinate planes; each plane holds a 3×3
square of lattice points, and all three squares intersect at a shared origin at
their common centre. Voices random-walk between adjacent points, and every point
sounds a note from a chosen scale.

Everything lives in one self-contained file, `lattice.md` — YAML frontmatter,
inline `<style>`, markup, `<script>`. Vanilla JS, zero dependencies, no build
step. Eleventy publishes it at `/demos/lattice/`.

---

## The figure

Points are the integer lattice `{-1,0,1}³` restricted to points with at least one
zero coordinate — the 27-point cube minus its 8 corners:

**19 points, 30 unit edges.**

Every edge falls into exactly one of two classes, and nothing else is possible:

| class | count | belongs to |
|---|---|---|
| plane boundary | 24 | exactly one plane (8 per plane) |
| coordinate axis | 6 | two planes at once — the shared spine |

*Why nothing else is possible:* if both of an edge's fixed coordinates were
non-zero, one endpoint would have no zero coordinate at all and so would not be
in the lattice. So for every real edge, exactly one fixed coordinate is zero
(→ one owning plane) or both are (→ an axis edge).

World space is **z-up**, so the octave axis reads as literally vertical and the
`z=0` plane — the one carrying the requested pitch set — is the horizontal floor.

## Pitch

Pitch is a **homomorphism from lattice position into scale-degree space**, then a
table lookup:

```
degree = gx·x + gy·y + gz·z + offset     →     SCALE.notes[degree] → MIDI → Hz
```

```js
SCALE = { name: 'D F G A B♭ C', notes: [50, 53, 55, 57, 58, 60], octave: 12 }
GEN   = { x: 1, y: 2, z: 6 }     // in scale degrees; gz = table length
tuning = { offset: 2, transpose: 0 }
```

The table wraps in both directions, adding `SCALE.octave` semitones per wrap:

```js
midiOfDegree(d) = SCALE.notes[mod(d, n)] + SCALE.octave · floor(d / n)
```

`gx = 1` (a scale step) and `gy = 2` (a third) make each plane a **tonnetz**: its
triangles are triads. `gz` equals the table length, so `z` is exactly an octave.

### Why scale degrees rather than frequency ratios

An earlier version mapped position to a *product of ratios*
(`f₀ · 2^z · (3/2)^x · (5/4)^y`), which is elegant but structurally rigid: every
step along an axis is forced to be the *same* interval, and only intervals
generated by the chosen primes can ever occur. That version could produce exactly
**6 interval sizes, ever**.

Because a scale is *uneven in semitones*, one lattice step is no longer one fixed
interval. Measured over a 600-tick run, this version sounds **12**:

```
-12  -5  -4  -3  -2  -1   +1  +2  +3  +4  +5  +12   semitones
```

A `y` step is a minor third, a major third, *or* a fourth depending on where the
voice stands. That unevenness is the entire source of harmonic variety.

**Just intonation is not lost.** `SCALE.notes` accepts fractional MIDI, so a just
major third above D3 is `53.8631`. Equal temperament and JI are both merely
*contents of the table*.

### The z=0 plane

`offset = 2` is chosen precisely because it places all six requested notes on
this plane:

```
  y= 1     57 A3     58 A#3     60 C4
  y= 0     53 F3     55 G3      57 A3     ← origin at centre, degree 2
  y=-1     48 C3     50 D3      53 F3
```

Seven distinct notes over nine points: C3, F3 and A3 each appear twice, because
degrees ±3 wrap. That is the accepted cost of the tonnetz generators — the
alternative (`gy = 3`) is one-to-one but loses the chordal logic.

### One mapping, shared by all three planes

A single global mapping means a point on a shared axis has **exactly one pitch**
regardless of which plane's voice is standing on it, so the origin stays a
genuine three-way unison. Per-plane mappings would break that. This is also why a
single note label per node is unambiguous.

Across the whole figure: 17 distinct notes over 19 points, spanning **D2 – A♯4**,
never straying outside the scale's pitch classes (C D F G A A♯).

## The walk

4-adjacency, orthogonal only — a voice steps along one of its plane's two free
axes, never diagonally. Two structural consequences:

**1. The origin is the most-visited point.** A simple random walk's stationary
distribution is proportional to degree, and under 4-adjacency a corner has 2
moves, an edge midpoint 3, the centre 4. So the origin gets `4/24 ≈ 1/6` of each
voice's steps — the unison is emphasised without any special-casing.

**2. The walk is bipartite.** Colour by parity of coordinate sum:
`{centre, 4 corners}` are even, `{4 edge midpoints}` odd. A 4-adjacent walk
alternates strictly between the two classes forever, so each voice's harmonic
rhythm alternates between two classes of sonority. Note this holds *within* a
voice; voices on different clock multipliers do not share a parity at a given
tick.

## The clock

One master pulse. Each voice steps every `mult` master ticks:

```js
state  = { masterMs: 1000, glide: 0.35 }
voices = [ { mult: 1 }, { mult: 2 }, { mult: 3 } ]   // → 1000, 2000, 3000 ms
```

Because the multipliers are **integers**, drift is impossible: every voice's step
lands on a master tick, and all three coincide exactly every `lcm(mults)` ticks —
every 6 at the defaults.

The critical detail is that phase is *derived* from the master clock rather than
accumulated privately:

```js
voicePhase(v) = ((state.tick mod v.mult) · masterMs + state.acc) / (masterMs · v.mult)
```

A private per-voice accumulator would drift with floating-point error and frame
jitter. This cannot. Verified over 600 s of deliberately jittery 8–33 ms frames:
zero drift, 100 exact three-way coincidences, zero stray.

### Motion

Between steps a voice's dot interpolates from `prev` to `next` with an eased
**snap-and-hold**: the move completes over the first `glide` fraction of that
voice's own period (default 35%), then holds. It reads as discrete events rather
than perpetual drifting, and it is the same parameter that drives audio
portamento — so motion and glide are one gesture.

## Audio

```
osc (sine) ──▶ gain ──▶ mute ──▶ master ──▶ destination
               tilt     0 or 1    volume
```

The context is created only inside a user gesture, per autoplay policy. Voices
are continuous drones that glide between pitches; there is no per-note envelope.

**Why mute is its own node.** `glideTo` writes a scheduled curve to the tilt
gain on every step. Folding mute into that same param would mean the two fight —
the next step would silently un-mute the voice. A separate node makes mute a
simple independent ramp.

**The glide curve.** `setValueCurveAtTime` receives `GLIDE_STEPS = 48` samples of
the *same* easing function the dot uses, interpolated **geometrically** (linear in
pitch, since lattice steps are multiplicative):

```js
f(i) = fromF · (toF / fromF) ^ easeInOutCubic(i / (GLIDE_STEPS - 1))
```

Wrapped in `try/catch` with an `exponentialRampToValueAtTime` fallback, because
an implementation may refuse a curve overlapping one still running. Note the API
takes a `Float32Array`, so frequencies are quantised to ~7 significant digits —
352.8 Hz becomes 352.79998779. That is ~6·10⁻⁸ cents, inaudible.

**Register tilt.** Equal-amplitude sines across three octaves read as wildly
unbalanced, so gain leans down as pitch rises, referenced to the origin:

```js
voiceGain(f) = clamp((originHz / f) ^ 0.45, 0.5, 1.35) · 0.28
```

*Known limitation:* the clamp saturates at the extreme low end, so there an equal
interval gives an unequal change in level.

Ramps: master 120 ms, mute 80 ms, retune 50 ms — all short enough to be
inaudible, long enough never to click. The context suspends on
`visibilitychange`, since the visuals freeze in a backgrounded tab anyway.

## Rendering

Canvas 2D, sized to the container and scaled by `devicePixelRatio`. The 3D
helpers (`dot3`, `cross3`, `norm3`, and the eye/forward/right/up + focal
projection) follow the hand-rolled camera in `corner-anamorphosis.md`, with the
eye moved onto spherical orbit coordinates and `lookAt` fixed at the origin.

```js
cam = { az: 0.86, el: 0.52, dist: 6.2, fov: 42 }
```

Elevation is clamped to ±1.5 rad so the up-vector never degenerates looking down
the z axis; distance to `[3, 14]`.

**Wireframe, no occlusion.** Rather than sort by depth, every element's alpha and
stroke width are cued from its mean camera-space depth:

```js
alpha: 0.75 → 0.18      width: 1.3 → 0.6      over ±FIG_R (1.5) around cam.dist
```

This avoids painter's-algorithm sorting entirely while still reading as
three-dimensional. Plane washes need no ordering either: all three squares are
centred on the origin, so their centroid depths are identical and draw order is
not observable.

Draw order: plane washes → 30 edges (boundaries in their plane's hue, the axis
spine in neutral grey) → 19 points → trails → voice dots → axis labels → note
labels. Note labels come last with a white knockout stroke so they stay readable
over the wireframe. A muted voice keeps walking but renders hollow, and its trail
drops to 35% alpha.

Palette reuses corner-anamorphosis's muted triad (`#8899cc`, `#88aa99`,
`#ccaa55`) so the demos read as a family.

`prj` and `cue` are the single source of truth for both outputs: the canvas and
the SVG export project through the same functions, so an exported file can never
disagree with the frame it was taken from.

## SVG export

`export svg` downloads the **instantaneous 2D projection** as a standalone SVG:
line paths for the wireframe, `<text>` for the labels. Dots, plane washes and
voice trails are omitted, so the file arrives in a vector editor as editable
geometry plus live, selectable type.

```
<svg viewBox="0 0 900 528">
  <g fill="none" stroke-linecap="round">
    <g id="plane-z0" stroke="#8899cc">  8 × <path d="M x y L x y" .../>
    <g id="plane-x0" stroke="#88aa99">  8 ×
    <g id="plane-y0" stroke="#ccaa55">  8 ×
    <g id="axis-spine" stroke="#555">   6 ×
    <g id="axis-labels">                6 × <text>+1 −1 +2 −2 +8ve −8ve</text>
    <g id="note-labels">               19 × <text>G3 …</text>
```

Every path is a plain two-point `M … L …` line — no curves, no compound paths —
and the grouping mirrors the figure's two edge classes exactly: 24 plane
boundaries in their plane's hue, the 6-edge shared spine in grey.

### Labels

The 19 note names follow the `notes` toggle, so `notes: off` exports the
wireframe plus axis labels alone. Both label groups reproduce the canvas exactly
— same font size, same offset above each node, same greys, the origin darker.

Two portability choices differ from the naive translation of the canvas calls:

- **The white knockout comes from `paint-order="stroke fill"`**, one attribute on
  the group, rather than from a duplicated stroke-then-fill element. The canvas
  needs two calls; SVG doesn't, and one element per label keeps the type editable.
- **The baseline is shifted by hand** (`y + 0.35em`) instead of with
  `dominant-baseline`. Canvas `textBaseline = 'middle'` has a direct SVG
  equivalent, but editor support for it is unreliable; an explicit offset renders
  identically everywhere.

`stroke-width` and `opacity` carry the same depth cue the canvas draws with, so
the file matches what is on screen. That does mean strokes as thin as 0.6 and as
faint as 0.18 — deliberate, but if the export is destined for a plotter or print,
strip those two attributes and the geometry stands alone.

`latticeSVG()` calls `updateCamera()` itself, so an export never depends on a
frame having just run, and it is deterministic for a fixed camera. Coordinates
round to 2 dp. A comment line records the camera (`az`, `el`, `dist`, `fov`) and
the scale, so a view can be reconstructed from the file.

Delivered as an `image/svg+xml` blob through a synthetic `<a download>`; the
object URL is revoked on a timeout rather than immediately, because some browsers
read the blob asynchronously after `click()`.

## Controls

**Bar:** `play/pause` (also spacebar) · `sound` · `vol` · `master ms` ·
`glide %` · `origin deg` · `transpose` · `notes` · `trails` · `auto-rotate` ·
`reset view` · `reseed` · `export svg`

**Per voice, in its readout row:** clock multiplier (`every N ticks`, with the
resulting period shown) and `mute`.

**Pointer:** drag to orbit, wheel to zoom.

Under `prefers-reduced-motion`, auto-rotate defaults off.

The readout shows, per voice: plane, coordinate, scale degree, MIDI note + name,
and frequency.

## Debug hooks

`window.__lattice` exposes state, the camera, voices, the audio graph, the pitch
functions, and — for the export — `latticeSVG()`, `prj()` and `cue()`. So
`copy(__lattice.latticeSVG())` in the console captures the current view without
touching the download, and `prj([1,0,0])` gives the screen position of any
lattice point.

`window.__lattice.audit(n)` runs `n` simulated steps and checks:

- every voice stays in its plane, inside the square, one unit per step
- parity alternates within each voice
- all six target notes appear on the `z=0` plane
- shared axis points have exactly one pitch
- `z` is exactly an octave everywhere

Returns `{ ok, points: 19, edges: 30, axisEdges: 6, spotChecks, errors }`.

## Where to change things

| lever | effect |
|---|---|
| `SCALE.notes` | **the main one.** Swap the scale and you swap the piece. Fractional MIDI gives just intonation |
| `SCALE.octave` | set ≠ 12 for a non-octave-repeating tuning |
| `GEN.x`, `GEN.y` | which intervals the axes generate. Keep them coprime with the table length or the plane collapses onto a few pitch classes — `gx=2, gy=4` over 6 notes yields only 3 |
| `GEN.z` | leave at the table length to keep `z` an octave |
| `tuning.offset` | which degree sits at the origin; shifts which notes land on each plane |
| `DEFAULT_MULT` | the polyrhythm. `lcm` sets how often all three coincide |
| `TRAIL_LEN`, `FIG_R`, depth-cue range | visual only — the depth cue also sets the exported `stroke-width`/`opacity` |
| `edgePath`, `svgText` | what the export emits per element; drop the cue attributes here for flat plotter output |

The one non-obvious constraint: **generators must generate the cyclic group of
the table length.** With a 6-note table, `gy = 2` and `gy = 4` are both even, so
they only ever reach the even subgroup `{0, 2, 4}` — three pitch classes out of
six. `gx = 1` guarantees full coverage.
